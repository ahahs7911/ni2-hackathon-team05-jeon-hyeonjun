## 2. 문제 정의와 프로젝트 기획

### 2-1. 문제 한 문장 (팀 확정)

> **현장 시설관리 담당자가 공조기 고장 증상이 생겼을 때 무엇부터 확인하고 A/S에 무엇을 알려야 할지 몰라 대응이 늦어지는 불편을, 증상별 점검 순서 안내와 A/S 접수 요약 생성으로 줄이는 웹앱**

| 칸 | 내용 |
|---|---|
| 사용자 | 병원·물류센터·관공서 등에서 서번 공조기를 운영하는 현장 시설관리 담당자 (공조 비전문가 포함) |
| 상황 | 공조기에 이상 증상이 생겼을 때 |
| 불편 | 무엇부터 확인해야 할지, A/S에 무엇을 알려야 할지 모름 → 대응 지연, 정보 누락, 위험한 임의 조치 |
| 핵심 기능 | ① 증상 → 점검 순서 안내, ② A/S 접수 요약 생성 |

### 2-2. 문제의 근거 종류

| 종류 | 상태 |
|---|---|
| **자료** | 있음. ㈜서번 공식 A/S 페이지 (S2, 2026-11-18)와 회사소개 페이지 (S3) |
| 관찰 | 없음 (미실시) |
| 인터뷰 | 없음 (미실시. 해커톤 중 기업 멘토에게 H1~H3 확인 예정) |

### 2-3. 핵심 기능 (MVP는 2개만)

1. **증상 → 점검 순서 안내**
   - 첫 단계는 언제나 **안전 확인**: 연기·타는 냄새·심한 소음/진동·전기부 근처 누수가 있으면 점검을 멈추고 "접근 금지 + A/S 요청 (화재 의심 시 대피·119)"으로 바로 넘어감.
   - 그다음 장비 → 증상 선택 → 사용자가 해도 되는 확인을 **한 단계씩** 제시 → 단계마다 [해결됨] / [안 됨] 버튼.
   - 단계마다 "하지 마세요" 경고를 함께 표시.
   - 안내 내용은 서번 공식 A/S 페이지(S2) 문구를 바탕으로 만들고, 장비별 사용설명서와 다를 수 있다고 표시.
2. **A/S 접수 요약 생성**
   - 끝까지 해결되지 않으면, 대화에서 받은 정보로 서번 A/S 문의 양식에 맞는 접수 요약문을 자동으로 만듦.
   - 항목: 문의 유형 / 현장명 / 장비 종류·번호·위치 / 증상 / 시작 시점·반복 여부 / 오류코드 / 이미 해본 조치 / 준비할 사진 목록.
   - [복사하기] 버튼 → 서번 홈페이지 A/S 양식이나 이메일에 붙여넣기. (실제 접수 전송은 MVP 범위 밖)

> 범위 밖 (나중에): 오류코드 사전, 자유 문장 입력 AI 분류, 사진 분석, 실제 접수 연동.

### 2-4. 화면 설계

**입력 화면 (대화형, 모바일 우선)**

1. 시작: "안전 확인" 카드. 연기/타는 냄새 · 큰 소음/진동 · 전기부 근처 물 → [있음] / [없음]
2. 장비 선택 버튼: 공기조화기(AHU) / 미리내(LSU) / 열교환기 / 공기순환기(ERV·HRV) / 잘 모르겠어요
3. 증상 선택 버튼: 고른 장비의 증상 목록 (예: 냉난방이 약해요, 바람이 약해요, 필터 차압 경보, 물이 떨어져요, 오류 표시 …)
4. 상황 질문 1~2개: 예) "화면에 중앙/원격 표시가 있나요?" "예열·제상 표시가 있나요?"
5. 점검 단계 카드: 할 일 1개 + "하지 마세요" 경고 + [해결됨] / [안 됨]
6. (안 됨일 때) 접수 정보 입력: 현장명, 장비 번호·위치, 시작 시점, 오류코드 (모르면 비워둠)

**결과 화면**

- 해결된 경우: "해결됨" 표시 + 어떤 단계에서 해결됐는지 + 다시 생길 때를 대비한 관리 팁 (예: 필터 관리).
- 해결 안 된 경우 (또는 안전 확인에서 걸린 경우):
  - 상단: **"A/S 점검이 필요합니다"** 와 위험도 배지 (긴급: 안전 이상 / 일반)
  - 가운데: **A/S 접수 요약 카드** (위 2번 항목) + [복사하기]
  - 아래: 준비할 사진 체크리스트 (오류 화면, 장비 이름표, 누수 부위 등), 연락처 051-831-7676 (ARS 2번) · as@seobun.co.kr
  - 하단 고지: "이 안내는 서번 공식 A/S 페이지를 바탕으로 한 시연용입니다. 실제 조치는 장비 사용설명서와 서번 A/S 안내를 따르세요."
